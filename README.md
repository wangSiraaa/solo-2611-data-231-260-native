# 分区事件流的贪心模式增量抽取

本目录仅含任务输入与可运行测试设施，不含待实现的处理器。

事件流水线需要从交错到达的多个分区中尽早抽出连续业务片段，并保留变量捕获的原事件。请用Python 3.11实现Matcher.push(event)和Matcher.end(partition)，以及读取stream.jsonl的命令。每分区内数值seq严格递增且event_id唯一，不同分区交错到达；END关闭对应分区，之后来数据应拒绝。输入CSV只供验收参考，正式处理入口必须逐条消费JSONL，不得读完全部事件排序后才匹配。没有时间戳、水位或迟到纠正。
模式是最多四个不同变量的串接，每项min/max满足1≤min≤max≤3；define为kind等值或value整数下界，一条事件可以满足多个变量。匹配由同分区连续行构成，每行只属于一个变量，不跳过内部事件。同一起点可能有多个完整分配，按模式变量顺序比较重复次数向量，字典序最大者是贪心结果；不能把B吞满后丢掉本可留给C的行。
每分区按起点顺序寻找匹配。当前起点若还有可延展为完整匹配的候选，则保留必要状态；已有完整候选但仍可能出现字典序更大的完整候选时不得提前发出。只要已到事件已使所有更大候选不可能，便在该次push返回最终匹配；若已无完整或可延展候选则推进起点并继续处理已缓存的行。END使未到行不再可能，须立即结清能形成的完整匹配。候选是否可延展只按已看到的行与模式判断，不能偷看未来输入。
成功后skip=next_row从该起点下一行继续，skip=past_last从最终匹配末行后一行继续；两策略可产生不同重叠结果。用有限状态或显式候选保留捕获信息，每分区未决原行缓存不超过模式最大总长度加1，已完成历史的原行和捕获状态不继续留在匹配器内；唯一性核验的ID元数据可另存集合或落盘，不计入原行缓存。记录各push输出、未决起点与缓存峰值，不能等整个分区结束再一次性返回。
每个结果给出模式、partition、起止事件、次数向量、各变量的event_id/seq列表及value总和，ID依输入身份和实际分配稳定构成。现成normal里B可能吞到end又须回退，且有必须等下一行才能确定的匹配和达到最大长度即可发出的匹配；另两模式对照重叠策略。用小数据批量穷举次数向量作为最终集合oracle，再手工核对关键push/END时刻的首次合法输出，分区交错方式改变不得影响各分区结果及在该分区第几条data/END后最终化，不比较全局push序号。不实现任意正则、嵌套重复、网络服务、恢复日志或大规模压测。
