# 给定函数依赖的关系分解与保真入仓

本目录仅含任务输入与可运行测试设施，不含待实现的处理器。

一份宽关系重复保存员工、部门及技能属性，业务方已经给出应长期成立的函数依赖。请用Python 3.11和SQLite实现小型分解工具，读取schema.json及CSV，产出分解方案、实际关系表和可重建的SQLite库。依赖是业务声明，不能从样例另外猜约束；最多六个非空字符串列，关系采用集合语义，重复完整元组拒绝，NULL不在范围内。
先按声明依赖逐条检查输入，违例给出决定列值及两条矛盾源行。将右部拆成单属性，依据属性顺序重复消除多余左部属性及冗余依赖，生成等价的最小覆盖；每次消除须记录相应闭包依据，不把样例中偶然成立的关系当证明。再按相同左部合并属性形成关系，删除被其他关系完整包含的关系；若没有任何关系含原模式一个候选键，补入按属性数、再属性顺序最小的候选键关系。
输出各关系属性、可作为键的决定集合，以及每条原声明依赖如何由投影到各关系的依赖闭包共同推出。范围小，可枚举属性子集求闭包，但不寻找全部最优分解、不做BCNF最小表数搜索。说明方案采用依赖保持的3NF构造，不能只因当前数据连接回来相等就宣称未来所有合法关系都无损。
按方案从真实输入投影去重并载入各SQLite表，保留规范字段类型与稳定表名。生成自然连接重建查询，实际执行后逐完整元组核对与原关系相同；不能偷偷保存另一份完整宽表作为重建答案。来源映射可单独保留每个投影行对应的原逻辑行号，不参与补造重建结果。
用给定冗余依赖、复合技能键和跨部门传递依赖运行；invalid.csv应定位姓名冲突并拒绝发布。更换CSV行序或依赖列出的顺序不改变规范方案。另检验没有非平凡依赖及需要补键关系的小例，交付闭包依据、实际数据库、重建SQL和README；不做在线迁移、兼容写视图或理论证明论文。

输入文件：
- `fixtures/schema.json`
- `fixtures/records.csv`
- `fixtures/invalid.csv`

环境：Python 3.11；全部业务数据为本地合成材料。
