# 混合类型复合键的字节序索引编码

本目录仅含任务输入与可运行测试设施，不含待实现的处理器。

底层键值存储只按bytes排序，但业务查询需要多列升降序、NULL位置和前缀范围。请用Python 3.11实现encode、decode、build和scan，按schema.json把int64、UTF-8 text、bytes及NULL复合键编码到SQLite的BLOB主索引列。SQLite只负责按BLOB字节排序与范围取数，不在查询时重新按业务列排序。row_id作为键外独立身份，相同业务键可对应多条记录并按row_id字节序稳定输出。
编码须无歧义可逆，字节序精确等价于各列order/nulls声明；负整数、最小最大int64、空串、空bytes、内嵌零字节与NULL均不同。文本采用UTF-8二进制顺序，不做locale或Unicode归一化；bytes输入用hex表示。降序时变长终止符与内容也参与次序，不能只倒置有效字节而使短前缀排错。hex只允许偶数位小写十六进制字符，空串合法；拒绝未知类型、非规范hex、错误值及超界整数。
scan支持若干起始列的等值前缀，并可对紧接其后的text列给starts_with。将它编译为一组有明确开闭界的BLOB区间，以区间查询读取候选，再做必要残余核对；不能扫描全部键解码后筛选。前缀不是完整tuple，不能把完整字段终止符错误放进文本前缀边界；上界不存在时应表达无穷边界，而非加一个不存在的最大字符。
保存格式版本、schema摘要及编码值，重开后可仅从编码还原业务键并查询。报告实际使用的字节界与读取键数，普通业务键字节不能与row_id后缀混淆。可以选择单条复合BLOB或键加row_id的联合索引，但必须公开布局与扫描规则；不实现B+树或自造数据库。
用给定样例核对全顺序和四个前缀查询，增加desc文本字段的短串/长串测试。独立按声明字段逐列比较的参考排序核对encode后的bytes排序，并对每条键验证decode。随机小数据枚举查询前缀验证无遗漏、无混入，窄前缀的实际读取应少于全表。交付源码、布局和运行说明，不做浮点NaN顺序、通用collation或压缩格式。

输入文件：
- `fixtures/schema.json`
- `fixtures/rows.jsonl`
- `fixtures/queries.json`

环境：Python 3.11；全部业务数据为本地合成材料。
