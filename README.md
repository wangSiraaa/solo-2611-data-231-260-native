# 预聚合表的安全复用与报表重聚合

本目录仅含任务输入与可运行测试设施，不含待实现的处理器。

明细库已经保存几张预聚合表，希望报表能安全复用它们，而不是把平均数再次平均导致口径改变。请用Python 3.11和SQLite实现plan与run，prepare.py提供真实fact和候选表，model.json声明同一事实快照、维度、度量及候选已应用的过滤条件。查询是给定JSON结构，只含group_by、各维度允许值集合的合取过滤及COUNT、金额SUM/AVG，不解析任意SQL。
候选的snapshot必须与查询事实快照相同；查询所需分组及剩余过滤须能由候选维度表示。候选已过滤的行域必须覆盖查询全部需要，不能拿只含A商品的表回答全商品或B商品。允许某查询条件已由候选谓词完全满足而无需该列，但不能凭当前数据恰好相同就假设谓词等价。NULL维度值作为独立组，允许值集合中的null表示匹配NULL。
COUNT由基础行计数求和，金额SUM须结合非NULL计数保持全NULL组的NULL结果；AVG必须用总SUM/总非NULLCOUNT重算，零分母返回NULL。只有avg_amount而没有权重的候选不够，不能按组数平均。无group_by的空结果仍输出一行count=0、sum/avg=NULL；有group_by则空结果无组。
为每个候选说明可用或被拒的具体原因。可用候选按实际候选表行数最少、再表名字节序选一个；不能读取fact明细计算答案后伪称用了汇总。生成并实际执行参数化SQL，保留使用表、残余过滤和重聚合表达式；没有可用候选时允许明确回退fact并说明原因。
对所有现成查询与独立直接fact聚合逐组对账，保留类型、NULL和精确SUM；AVG可输出分子/分母或声明精度的小数。记录实际读取表，验证avg-only、旧snapshot和错误过滤域被拒；不同大小子组的AVG必须按有效行数加权。新增一条查询证明不是按query_id硬编码。范围为单事实和少量预聚合，不做多事实连接、自动建表、增量维护或成本最优搜索。
