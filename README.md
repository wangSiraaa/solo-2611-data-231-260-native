# 多排序索引的阈值TopK取数

本目录仅含任务输入与可运行测试设施，不含待实现的处理器。

同一批对象的两个属性各有降序索引，报表要按正整数加权总分取前K名，不能先把所有对象读完才排序。请用Python 3.11实现query客户端，使用给定真实HTTP索引服务的sorted scan与按ID lookup，接口和访问限制见protocol.md。服务不提供总分排序；客户端不直接读取服务端rows.json或验收inspect。
先固定snapshot，两路分页各自保留游标和最后读到的得分。按确定策略推进索引，对首次遇到的对象随机补齐另一个属性，缓存同一对象的完整分数，不能因两个索引都遇到它就重复候选或重复lookup。总分用精确整数，排序为总分降序、ID UTF-8字节序，K大于对象数时返回全部。
为完全未见对象建立当前总分上界：两路已扫描前缀之外的分数不超过各自最后得分。只有已有足够完整候选且可以证明未见对象不会进入最终K名时才停止；第K名与上界同分时不能忽略潜在更小ID，保守继续读取即可。某一路耗尽、空数据和尚未读到首项需要单独处理，不能把未知阈值填0。每次停止需给出已见集合、两路前沿、阈值与第K名依据。
输出每个命中的两列原分数与总分、实际scan/lookup请求及停止理由。请求或响应snapshot变化则本次失败，不把两个快照的分数组合；重试不能悄悄重新开始另一个snapshot后沿用旧候选。无需持久续跑或分布式索引。
用给定并列b/c/d及不同page_size核对结果，独立读取服务端原数据仅用于验收全量排序。至少top2查询应在读取完两个索引前正确停止，证明减少的是实际接口返回项数；同分情况下仍保证ID裁决。启动change-after服务验证快照失效不发布成功结果。交付源码、请求计数和README，不实现近似搜索、任意模型打分、普通全量外排序或成本最优调度。
